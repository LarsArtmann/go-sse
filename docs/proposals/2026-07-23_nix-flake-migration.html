00Summary

The migration is complete and verified. A new flake.nix adopts the same proven pattern already used by the sibling pure-library repos (go-branded-id, go-error-family, go-ndjson): flake-parts + treefmt-nix + systems, with apps for local development and a devShell that pins Go 1.26 with GOEXPERIMENT=jsonv2.

The bottom line The one material difference from the leaf libraries: go-sse has dependencies, so its hermetic check cannot use a bare runCommand + go build (that needs network). Instead checks.build uses buildGoModule with a vendorHash, making nix flake check fully reproducible and offline.

nix flake check passes (format + build). The devShell enters cleanly with the correct environment. The public dependencies resolve through the Go module proxy, so no mkPreparedSource / GOPRIVATE machinery is required.

01Decision: manual flake-parts, not go-standard

The nix-flake-migration skill recommends the shared flakeModules.go-standard module for LarsArtmann Go projects. That module is built around a binary: it sets apps.default = lib.getExe config.packages.default, meta.mainProgram, and version-injection ldflags. go-sse is a pure library with no main package, so go-standard would emit an app that points at a non-existent executable.

Justified exception

go-standard assumes a binary; this is a library

flakeModules.go-standard · apps.default / meta.mainProgram

Adopted the manual 4-input flake-parts pattern instead. It is the established convention for every pure-library repo in this ecosystem, and it gives full control over the library-appropriate shape: no packages.default, no overlay, no mainProgram. The tradeoff is ~130 more lines than a 20-line go-standard flake, but those lines are exactly the library-specific structure go-standard cannot express.

What the flake provides

+
Hermetic compile + test check buildGoModule vendors go-branded-id and go-error-family via vendorHash; nix flake check is offline-reproducible.
+
treefmt with gofumpt, goimports, golines, nixfmt Single formatter (nix fmt) and a format check, matching the sibling libraries.
+
Pinned, environment-correct devShell Go 1.26, GOEXPERIMENT=jsonv2, GOWORK=off, GOTOOLCHAIN=local baked in as attributes, not shell exports.
+
Dev apps with GOEXPERIMENT test, test-race, build, vet, lint, coverage, clean; each exports GOEXPERIMENT=jsonv2 (required transitively via go-branded-id).

03The flake.nix

The complete, working flake (176 lines). Key structure annotated inline.

{
  description = "Server-Sent Events transport for Go (wire format, fan-out, replay)";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    flake-parts = {
      url = "github:hercules-ci/flake-parts";
      inputs.nixpkgs-lib.follows = "nixpkgs";
    };
    systems.url = "github:nix-systems/default";
    treefmt-nix = {
      url = "github:numtide/treefmt-nix";
      inputs.nixpkgs.follows = "nixpkgs";
    };
  };

  # outputs = flake-parts.lib.mkFlake { inherit inputs; } { systems, treefmt, perSystem }
  # perSystem let:
  #   goPkg = pkgs.go_1_26;
  #   buildGoModule = pkgs.buildGoModule.override { go = goPkg; };
  #   vendorHash = "sha256-pu25vX8Vo31Ei2nNRzUomG9/ADdB3EFamTO0D+Z5QB4=";

  # Hermetic check: vendors the public deps, compiles, and runs go test ./...
  hermeticCheck = buildGoModule {
    pname = "go-sse";
    src = lib.fileset.toSource { root = ./.; fileset = lib.fileset.gitTracked ./.; };
    subPackages = [ "." ];
    proxyVendor = true;
    doCheck = true;
    env.GOEXPERIMENT = "jsonv2";
  };

  # checks.format = treefmt;  checks.build = hermeticCheck;
  # devShells.default + .ci: mkShellNoCC, GOEXPERIMENT=jsonv2, GOWORK=off, GOTOOLCHAIN=local
  # apps: test, test-race, build, vet, lint, coverage, clean (each exports GOEXPERIMENT=jsonv2)
}

Note GOEXPERIMENT=jsonv2 appears in three places: the hermetic build (env.GOEXPERIMENT), the devShells (as an attribute), and every Go dev app (exported in the script text). This is required because go-sse compiles go-branded-id, which uses the jsonv2 APIs.

04Private dependencies: not needed

The nix-private-go-repos skill was invoked to evaluate whether mkPreparedSource + GOPRIVATE handling is required. It is not.

go-sse ├── github.com/larsartmann/go-branded-id PUBLIC (proxy hash in go.sum) └── github.com/larsartmann/go-error-family PUBLIC (proxy hash in go.sum)
  • Both deps resolve from the public Go module proxy (go mod download with GOPRIVATE=none succeeds).
  • Neither is in the host's global GOPRIVATE list (which covers go-cqrs-lite, go-finding, go-structure-linter, go-commit).
  • Therefore: no deps map, no git+ssh flake inputs, no GOPRIVATE in devShells. vendorHash alone makes the build hermetic.
If a dep ever goes private Add it as a git+ssh flake = false input and move the flake to the go-standard module (or manual mkPreparedSource) with a non-empty deps map. The skill's gotcha table covers the mixed-casing GOPRIVATE fix.
