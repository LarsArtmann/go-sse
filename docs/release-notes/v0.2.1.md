# v0.2.1 Release Notes

**Tag:** `v0.2.1` — 2026-07-26

Patch release of `go-sse`. **No public API changes** — no new exports, no
breaking changes, no behavioural shifts. This release is about reliability and
confidence: flaky tests eliminated, 100% test coverage, and two new end-to-end
integration tests proving the two most critical SSE paths over a real HTTP
round-trip.

Upgrade is safe and mechanical: `go get github.com/larsartmann/go-sse@v0.2.1`.

## Highlights

- **100% test coverage** of statements (up from 97.9% in v0.2.0).
- **Zero flaky tests** — the two remaining `time.Sleep`-based tests now wait
  deterministically on channel signals.
- **Real-HTTP integration tests** for heartbeat keep-alive delivery and
  `Last-Event-ID` reconnection replay.
- **CI hardening** — `govulncheck` and fuzz jobs added.

## Quality

- **100.0% test coverage**, all tests pass with `-race` (count=2) and
  `-count=10` on the previously-flaky tests.
- **golangci-lint** clean (0 issues).
- **New integration tests:**
  - Heartbeat comment-frame delivery over a real HTTP round-trip (the proxy
    keep-alive path — the most common silent-failure mode for SSE).
  - `Last-Event-ID` reconnection replay over a real HTTP round-trip (the core
    SSE reconnection use case).
- **New unit tests:** `eventBrand.Name()` (via `EventID.String()`), the
  `MustParseEventID` success path, and the `Stream.Heartbeat` write-error exit
  path.
- **Flaky tests eliminated:**
  - `TestIntegration_BroadcasterFanOut` — replaced `time.Sleep(200ms)` with an
    `OnUnsubscribe` channel signal.
  - `TestStream_Heartbeat` — replaced `time.Sleep(50ms)` with a
    concurrency-safe recording writer that signals on each write. (The previous
    test read `httptest.ResponseRecorder.Body` from the test goroutine while the
    heartbeat goroutine wrote to it — a latent data race.)

## CI

- **`govulncheck` job** added to `.github/workflows/ci.yml`.
- **Fuzz job** added — runs `FuzzWriteEvent` and `FuzzParseEventID` for one
  minute each on every PR.

## Changed

- `go-error-family` dependency bumped from `v0.8.0` to `v0.9.0`.
- Removed an unreachable defensive branch in `splitLines` (verified
  unreachable) — closed the last coverage gap.
- Test modernization: `context.WithCancel(context.Background())` →
  `context.WithCancel(t.Context())`; `wg.Add` + `go func()` + `defer wg.Done()`
  → `wg.Go` in race tests.
- Doc/source/README examples corrected to
  `defer func() { _ = stream.Close() }()` (`Stream` satisfies `io.Closer`)
  instead of `defer stream.Close()` — copy-pasteable snippets no longer fail
  `errcheck`.

## Requirements

- Go 1.26+
- `GOEXPERIMENT=jsonv2` (transitive dependency via `go-branded-id`)

## Dependencies

Two same-author utility modules (the only `require` entries):

- `github.com/larsartmann/go-branded-id` — phantom-type branded IDs
- `github.com/larsartmann/go-error-family` — structured error wrapping

## Installation

```bash
go get github.com/larsartmann/go-sse@v0.2.1
```

## Stability

This is a `v0` release — the public API may change before `v1.0`. The core
types (`Event`, `Stream`, `Broadcaster`, `Replay`) are stable in practice, but
breaking changes in minor versions are possible. This **patch** release changes
no public API.

## Known issue (pre-existing, not introduced by this release)

`nix flake check` currently fails with a `vendorHash` mismatch: the
`go-error-family` `v0.8.0` → `v0.9.0` bump (already present at the v0.2.0
boundary) was not reconciled with the `vendorHash` in `flake.nix`. The Go
module itself builds and tests cleanly (`go build`, `go test -race`, `go vet`,
`golangci-lint` all green); only the Nix hermetic build is affected. This is
tracked for a follow-up fix and does **not** affect downstream `go get`
consumers.
