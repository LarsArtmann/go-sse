# v0.2.0 Release Notes

**Tag:** `v0.2.0` — 2026-07-24

Second release of `go-sse`. This version adds batch fan-out, JSON and debug
conveniences, and stronger error propagation — plus two breaking API changes
that make the public surface more honest.

## Breaking changes

Two mechanical migrations; both improve API honesty without changing behaviour.

### 1. `Stream.SendHTML` → `Stream.SendData`

The method sends any raw string, not just HTML. The old name was misleading.

```diff
- stream.SendHTML("update", html)
+ stream.SendData("update", html)
```

### 2. `EventStore.EventsAfter` now returns `([]Event, error)`

Implementations can fail (database errors, network timeouts). Previously
`Replay` silently treated failures as "no events". Now the error propagates.

```diff
  func (s *myStore) EventsAfter(lastID sse.EventID) []Event {
-     return s.db.Query(lastID)
+ func (s *myStore) EventsAfter(lastID sse.EventID) ([]Event, error) {
+     return s.db.Query(lastID)
  }
```

## What's new

### Core

- **`Broadcaster.BroadcastMany(msgs ...T)`** — batch fan-out in a single locked
  pass. Cheaper than looping `Broadcast` (one `RLock` instead of N) and
  guarantees per-subscriber ordering across the batch. Slow subscribers with
  full buffers still have individual messages dropped, exactly like `Broadcast`.
- **`Stream.SendJSON(eventName string, v any) error`** — convenience counterpart
  to `SendData` that JSON-marshals the payload (returns the marshal error or the
  write error).
- **`Event.String()`** — compact, human-readable representation for logging and
  debugging. Omits empty fields so logs stay readable. Not the wire format.
- **`Replay` store-error propagation** — `Replay` now wraps and returns
  `EventsAfter` errors via `go-error-family` (code `sse.replay_store_failed`,
  severity `Rejection`) instead of silently swallowing them.

### Developer experience

- **Go `Example` functions** rendered in godoc (`ExampleWriteEvent`,
  `ExampleBroadcaster`, `ExampleParseEventID`) — runnable, testable snippets.
- **Expanded `example/` server** demonstrating replay and advanced SSE features.

### Quality

- **97.9% test coverage**, all tests pass with `-race`
- **New tests:** `SendJSON` (happy-path, marshal-error, nil-value), `Send`
  write-failure, concurrent `Send`+`Close` and three-way
  `Send`+`Heartbeat`+`Close` race safety, `BroadcastMany` (delivery, ordering,
  empty, mixed-slow-fast), `Event.String` field-omission matrix, `Replay` store
  error
- **Benchmarks:** fan-out extended to 10,000 subscribers; zero-allocation at all
  scales (37 ns/op at 1 sub → 2.5 ms/op at 10k subs);
  `BenchmarkBroadcastManyVsLoop` quantifies the batch-API advantage
- **golangci-lint** clean (0 issues)
- **Deterministic test sync** — `BroadcastMany` mixed-slow-fast test rewritten to
  use channel synchronization instead of `time.Sleep`, eliminating CI flake risk

## Quick start

```go
broadcaster := sse.NewBroadcaster[sse.Event]()

// SSE endpoint
http.HandleFunc("/events", func(w http.ResponseWriter, r *http.Request) {
    stream := sse.NewStream(w, r)
    defer stream.Close()

    go stream.Heartbeat(stream.Context(), 15*time.Second)

    ch := broadcaster.Subscribe()
    defer broadcaster.Unsubscribe(ch)

    for {
        select {
        case <-stream.Context().Done():
            return
        case evt := <-ch:
            if err := stream.Send(evt); err != nil {
                return
            }
        }
    }
})

// Broadcast a batch in a single locked pass
broadcaster.BroadcastMany(
    sse.Event{Event: "update", Data: "<div>1</div>"},
    sse.Event{Event: "update", Data: "<div>2</div>"},
)

// Or send a JSON payload directly
stream.SendJSON("snapshot", myStruct)
```

## Stability

This is a `v0` release — the public API may change before `v1.0`. The core
types (`Event`, `Stream`, `Broadcaster`, `Replay`) are stable in practice, but
breaking changes in minor versions are possible.
