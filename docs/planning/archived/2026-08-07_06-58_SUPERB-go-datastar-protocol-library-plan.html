00Problem & Solution

The Problem starfederation/datastar-go couples patch construction to a live SSE connection (Patch.apply(*ServerSentEventGenerator)). Patches are not values — you cannot queue, filter, replay, or broadcast them. This forced cqrs-htmx/datastar to hand-roll 286 lines of fan-out, replay, heartbeat, and EventID logic that go-sse already provides. The SDK's ServerSentEventGenerator is just a standard SSE writer (15% of its code); the other 85% is protocol vocabulary locked behind method-call semantics.
The Solution Build go-datastar — a standalone companion to go-sse where Patch is an interface with Event() sse.Event. Patches become first-class values: storable, filterable, replayable, broadcastable. The protocol vocabulary (ElementsPatch, SignalsPatch, ScriptPatch, etc.) is reimplemented as value-producing constructors. go-sse owns transport; go-datastar owns protocol. cqrs-htmx/datastar drops the SDK dependency and 286 lines of duplicated transport, gaining Shutdown/Health/SubscribeFilter for free.

Target Architecture

go-sse
transport layer
Stream, Broadcaster[T], Replay, EventID, Heartbeat, SubscribeFilter, Shutdown, Health
↑

The Keystone Design Decision

// go-datastar: patches are VALUES, not method calls
type Patch interface {
    Event() sse.Event  // produce the final SSE wire-format event
}

// Usage with go-sse's generic Broadcaster:
broadcaster := sse.NewBroadcaster[sse.Event]()
patch := datastar.NewElementsPatch(html, datastar.WithSelector("#feed"))
broadcaster.Broadcast(patch.Event())  // store, fan-out, replay as sse.Event

// Or broadcast patches directly (for typed filtering):
patchCaster := sse.NewBroadcaster[datastar.Patch]()
patchCaster.Broadcast(patch)
// consumer: evt := <-ch; stream.Send(patch.Event())

08Key Design Notes

Wire-Format Parity Requirements

These behaviors must be reproduced exactly from the SDK:
  • Mode outer is never emitted on the wire (it's the default)
  • Namespace html is never emitted (default)
  • Retry duration gate differs per patch type: Elements checks > 0; Signals checks != DefaultSseRetryDuration
  • AutoRemove is *bool: nil and true both add data-effect="el.remove()"
  • ExecuteScript always uses selector: body + mode: append
  • Elements split on \n (not CRLF); each line gets its own data: elements ...
  • Signals split on \n via bytes.SplitSeq; every line emitted unconditionally
  • ReadSignals accepts GET or DELETE from ?datastar= query; others from JSON body
  • Dataline keys have trailing space baked in: "selector ", "elements ", etc.
  • ConsoleLog/Error use %q for JS string quoting
  • DispatchCustomEvent defaults bubbles/cancelable/composed=true, selector=document

API Improvement Over SDK

Where go-datastar is BETTER than the SDK:
  • Patches are values — storable, filterable, replayable, broadcastable. SDK patches are method calls on a live connection.
  • MarshalSignals returns error instead of panicking. SDK's MarshalAndPatchSignals panics on marshal failure.
  • No MarshalAndPatchSignalsIfMissing aliasing bug — SDK mutates the caller's opts slice via append.
  • No WithExecuteScriptAttributeKVs panic — go-datastar returns an error on odd arg count instead.
  • Patches are testable without a connection — construct, call .Event(), assert on the result.
  • Composable with go-sse — Broadcaster, SubscribeFilter, Replay, Shutdown, Health all work out of the box.
