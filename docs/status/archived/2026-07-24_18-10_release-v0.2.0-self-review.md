## e) WHAT WE SHOULD IMPROVE (process lessons)

1. **Audit all user-facing docs BEFORE tagging, not after.** The README errors were detectable by simply running the code samples against the actual API. I should have a pre-release checklist that includes "every code sample in README compiles and matches current API."
2. **Verify author attribution on commits.** When a hook creates a commit with `Unknown Author`, fix the author with `git commit --amend --author="..."` before finalizing, especially on release commits.
3. **Push the branch before (or simultaneously with) the tag.** A tag pointing at a commit that isn't on the branch tip on remote creates a confusing state for contributors.
4. **Order of operations for releases should be:** fix all docs → commit → verify → tag → push branch → push tag → create GitHub release. I did: tag → create release → then notice README is broken.
5. **Run a verification pass against pkg.go.dev after release.** The homepage link points there; if it's not live, the repo's homepage 404s.
